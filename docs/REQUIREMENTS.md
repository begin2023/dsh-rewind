## 0. 先把误会说清楚

- 之前的 `rewind-chat` 是一个**独立网页 Demo**（自己起服务、自己存 SQLite），不是 DSH 插件，所以插件市场里永远不会有它。
- 你要的是**DSH Web 插件**：装进 DSH、重启后直接出现在 DSH 聊天界面里，每条消息下面多出几个按钮。
- 这一稿只谈需求与做法，代码一行不动，等你点头。

## 1. 目标（你的原话）

> 在一个会话里面对某一条会话进行编辑、撤回、重发；还要考虑图片请求，不能漏了图片或者别的文件。

拆成四条硬要求：

1. **任意一条消息**都能：编辑、撤回、重发。
2. 操作后**图片不能丢**，其他附件（md/pdf/zip…）也不能丢。
3. 操作发生在**同一个会话的上下文里**，不是另开一个空白对话。
4. 交互要完整：确认、撤销、失败提示、移动端、深浅色都要有。

## 2. 交付形态

一个标准 DSH 插件包（和 `dsh-weight-journal` 同构）：

| 组成 | 内容 |
| --- | --- |
| 包名 | `dsh-rewind`（可改） |
| 安装 | 软链到 `~/.dsh/profiles/desktop/node_modules/dsh-rewind`，并在 `cordis.patch.yml` 加一条 loader 记录 |
| 前端 | `client.js`，通过 DSH 的 Slot 机制把按钮挂进聊天流 |
| 宿主 | `index.js`，可选：提供 `rewind_* ` 工具与持久化 |
| 数据 | 插件自有 storage（`~/.dsh/storages/rewind.json`），不碰 DSH 会话文件 |

## 3. 功能需求

### 3.1 用户消息

- **编辑**：就地展开编辑框，文字可改，**附件以缩略图/文件条形式一起展示并可增删**；保存后从这条消息处重新开始。
- **撤回**：二次确认；说明会影响后面几条；撤回后顶部出现「撤销」。
- **重发**：把原文 + 全部附件放回输入框（或立即发送），图片仍是图片，文件仍是文件。

### 3.2 助手消息（建议一并做）

- **重新生成**：从这条助手回复重新跑一次。
- **撤回**：仅当它是最后一条时可用；否则提示会连带撤回后续。
- （可选）**版本切换**：v1 / v2 来回切。

### 3.3 附件保真（重点）

| 场景 | 要求 |
| --- | --- |
| 编辑后保存 | 原有图片、文件全部带过去；用户新加的也算 |
| 撤回 | 附件不删除，撤销后原样回来；插件侧保留引用 |
| 重发 | 图片按 base64 重新提交；文件按 receipt 重新提交；失败的附件单独提示，不静默丢 |
| 大小限制 | 沿用 DSH 自身的上限，超限时明确报错 |

技术上已验证：DSH 的 `prompt` 接受 `text | image(mediaType,data,name) | file(receiptId)` 三种片段，所以"重发带图"是可行的；图片字节可通过 `readAttachment` 读回。

## 4. 关键约束：DSH 的会话是"追加式日志"

这是必须先讲清楚的一点，直接决定"编辑/撤回"能做到什么程度。

- DSH 的会话存储在 `~/.dsh/sessions/<workspace>/<session>/session.v4.jsonl.zstd`，**追加写**，运行中还被 `session.lock` 锁住。
- 宿主提供的会话命令只有：`create / selectModel / rename / fork / prompt / attachment / updateQueue`。
- **没有** `truncate` / `rewind` / `edit` 这类"改写历史"的命令。官方给每条消息的按钮只有「复制」和「分支」。
- `fork({ sessionId, atSeq })` 可以**从某条消息处切一个新分支**，这是唯一受支持的"回到过去"方式。

由此有三条路线：

| 路线 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| **A. 分支（推荐）** | 编辑/撤回后，从该消息处 `fork`，在新分支里发新内容 | 官方 API，安全；模型上下文真的变了；旧内容可回看 | 会多出一个会话条目（DSH 的分支就是一个新会话）；不是"原地" |
| **B. 原地改写** | 插件直接解压、截断、重写 `session.v4.jsonl.zstd` | 真正做到"同一条会话里消失" | 会话运行中被锁；改完要重启/重载；写坏就是丢对话。**不建议** |
| **C. 纯界面隐藏** | 只在 UI 上盖住这条消息 | 最简单 | 模型仍然记得它，等于骗自己。只适合"眼不见" |

我的建议：**A 为主**，撤回时提供「仅隐藏（可撤销）」或「从这里分叉（模型也忘掉）」两个选项，把 C 作为 A 的一个降级动作。

## 5. 交互稿（文字版）

```
┌──────────────────────────────────────────────┐
│  用户消息气泡                         12:25  │
│  帮我看看这张图和笔记，规划路线               │
│  [图片缩略图] [徒步笔记.md]                   │
│                                              │
│        悬停时出现在气泡右下方：               │
│        [编辑] [重发] [撤回]  ← 与 DSH 原生    │
│                              复制/分支同排    │
└──────────────────────────────────────────────┘
```

- **编辑态**：气泡下方展开编辑面板（文字域 + 附件区 + 取消/保存），Esc 取消，⌘Enter 保存。
- **撤回**：确认弹窗写清楚"将同时撤回后续 N 条"，确认后消息变灰并显示「已撤回 · 撤销」。
- **重发**：附件随文字回到输入框，顶部提示条带「立即发送」。
- **失败**：附件上传失败时，卡片标红并给出"重试/移除"，绝不静默消失。
- **移动端**：按钮常驻（无 hover），底部抽屉承载编辑面板。
- **主题**：跟随 DSH 深浅色，不写死颜色。

## 6. 边界情况清单

- [ ] 正在流式生成时编辑/撤回 → 先停止生成或禁用按钮（二选一，需你定）
- [ ] 排队中的消息（queue / steer）
- [ ] 子代理会话（subagent）里是否显示按钮
- [ ] 跨窗口/跨刷新后状态是否保持
- [ ] 撤销时限（建议 7 天，和 Demo 一致）
- [ ] 附件在磁盘被删除后的降级显示
- [ ] 会话被 fork 后的版本归属

## 7. 非目标

- 不做独立网页服务（那是之前的 Demo）。
- 不改 DSH 的会话存储格式。
- 不做跨会话搜索/导出（除非你另外要）。

## 8. 验收标准

1. 装好插件、重启 DSH，聊天里每条用户消息可见「编辑 / 重发 / 撤回」。
2. 带 2 张图 + 1 个 md 的消息，编辑后图片与文件仍在，模型收到的是新内容。
3. 撤回后消息消失（或标灰），点撤销能原样回来，附件完好。
4. 重发后新消息带全部附件，图片在模型侧仍是图片（不是占位符）。
5. 深浅色、移动端、键盘操作都正常，无 console 报错。
