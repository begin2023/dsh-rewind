# 功能与实现边界

本文描述当前发布版的行为，供贡献者审查消息投影、附件和异步操作时参考。使用方法见 [中文 README](../README.md) 或 [English README](../README.en.md)。

## 消息操作

- 用户消息只有「编辑」入口。编辑器展示正文及已有附件，支持保留、移除和追加附件；正文不变也可以提交。
- 助手回复只有「重新生成」入口，复用该回复之前最近一条真实用户输入及其附件。
- 两种操作都在同一会话中继续。它们保留目标用户输入之前的上下文，并替换该输入及所有后续可见消息。
- 独立的重发和撤回入口已移除；仍识别旧版本的撤回标记，以便显示历史状态及恢复原始输入。

## 历史与模型上下文

宿主实现位于 [index.js](../index.js)，浏览器模块位于 [client.js](../client.js)。插件不直接覆盖会话文件，不建立独立历史数据库，也不通过新会话分支模拟原地修改。

宿主向追加式日志写入空内容的 `system/message`，通过 `surfaceOp: { op: "replace", startSeq, endSeq }` 替换目标区间。标记 ID 为 `rewind:<kind>:<uuid>`；`sourceEventSeqs` 记录被替换的 Surface 节点。空内容不会成为供应商消息；被替换的节点退出当前消息投影。原始日志仍保留。

浏览器通过会话节点插槽提供操作，使用独立样式表隐藏旧内容、显示替换标记。编辑标记上的「放回输入框」恢复原始用户输入，不会撤销截断、自动恢复后续回答或回滚外部操作。界面没有历史版本展开或任意版本切换功能。

## 修改前检查

在改动消息投影之前，必须完成目标校验、代理查找、附件读取和宿主内容准入检查。存在排队输入时拒绝操作；生成中使用保留 inbox 的取消方式，并等待 `whenIdle()`。包括维护状态在内，等待空闲的上限为 6 秒。取消失败、等待超时、会话重新加载或代理仍忙碌时，不写替换标记。

同一会话的编辑和重新生成互斥；不同会话独立。等待结束后重新检查会话、代理和目标节点。替换标记和后续输入的入队之间没有异步让出点，避免刷新持久化时混入其他输入。日志持久化沿用宿主服务。

## 附件

- 编辑及重新生成使用原始图片／文件引用，不以文件名占位符代替内容。
- 读取原图片的实际字节数交给宿主准入服务，沿用其总图片大小和格式限制；文件必须能完整读出。任何读取或准入失败发生在截断前。
- 新上传内容使用严格 Base64 解码。允许空文件；空图片拒绝。图片由宿主图像存储验证。
- 保存开始时固定正文和附件快照，并禁用编辑、移除、粘贴和拖入；保存期间不能通过 Esc 或遮罩关闭。插件卸载强制关闭后，尚未提交的保存任务失效。
- 历史恢复会读取原始附件、创建宿主草稿并追加到输入框。恢复期间阻止重复点击；组件卸载或输入会话切换后，不再把异步下载的附件放入输入框。读取失败会提示具体附件。

## 验证与兼容性

离线测试使用 Node.js、React 和 jsdom，覆盖加载、投影映射、路由、附件、渲染及交互失败路径。测试路径相对仓库定位，不依赖作者机器的临时目录。CI 在 Node.js 20、22、24 上运行。

发布验证使用 DSH 桌面运行时 `0.2.2-rc.2` 的真实 Session → AgentLoop → PiAi 流程连接本地 HTTP 接收端，检查编辑后的供应商请求 JSON。它验证真实序列化边界，但不是生产会话抓包，也不代表已验证所有供应商协议。

插件依赖宿主 Session Surface、附件服务和客户端插槽 API。宿主升级可能改变这些接口，需要重新验证。当前插件 UI 为中文；中文 README 为主文档，并提供独立英文 README。
